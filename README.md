# Study Tasks API

API на FastAPI для учёта учебных задач. Можно добавить задачу, отметить её
выполненной, отфильтровать список и посмотреть статистику. Подходит для
небольшого личного списка заданий студента.

Задачи хранятся в памяти и удаляются при перезапуске. Сервер нужно запускать
в одном процессе, без нескольких `--workers`. Авторизации и базы данных нет.

## Установка

Требуется Python 3.12.

```bash
git clone https://github.com/Lambersss/study-tasks-service.git
cd study-tasks-service
```

macOS / Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
```

Если активация в PowerShell недоступна, используйте
`.\.venv\Scripts\python.exe` вместо `python` в командах.
Для запуска без тестов достаточно зависимостей из `requirements.txt`.

## Запуск

Из папки проекта с активированным окружением:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Документация API: <http://127.0.0.1:8000/docs>.
Запросы можно выполнить прямо там через **Try it out** и **Execute**.
Остановка сервера — `Ctrl+C`.

Проверка состояния и версии в другом терминале:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
```

Ответы: `{"status":"ok"}` и `{"version":"1.0.0"}`.
В PowerShell используйте `curl.exe` или откройте адреса в браузере.

Для разработки можно добавить `--reload` к команде запуска.
При каждом перезапуске список задач очищается.

## Настройки

Настройки необязательны. Чтобы изменить значения по умолчанию, скопируйте
`.env.example` в `.env` и отредактируйте его:

```bash
cp .env.example .env
```

В PowerShell: `Copy-Item .env.example .env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_NAME` | `Study Tasks API` | Название в `/` и `/docs`, непустая строка |
| `MAX_TASKS` | `100` | Максимум задач, включая выполненные; целое число больше нуля |
| `LOG_LEVEL` | `INFO` | Уровень логов: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |

Приложение читает `.env` рядом с `app_final.py`. Переменные окружения процесса
имеют приоритет. После изменения настроек сервер нужно перезапустить.
При неверном значении запуск завершается с указанием переменной.

`.env` исключён из Git. В репозитории хранится только `.env.example`.
Пароли и токены для работы сервиса не нужны.

## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Название и ссылка на документацию |
| GET | `/health` | Проверка работоспособности |
| GET | `/version` | Версия приложения |
| POST | `/tasks` | Создать задачу |
| GET | `/tasks` | Список задач; фильтр `?completed=true` или `false` |
| GET | `/tasks/{task_id}` | Получить задачу по ID |
| PATCH | `/tasks/{task_id}` | Изменить признак выполнения |
| DELETE | `/tasks/{task_id}` | Удалить задачу |
| GET | `/stats` | Количество всех, выполненных и оставшихся задач |

Название задачи — от 1 до 120 символов, пробелы по краям удаляются.
ID должен быть положительным числом. Неизвестная задача возвращает `404`,
ошибка в данных — `422`, превышение `MAX_TASKS` — `409`.
Удаление задачи освобождает место в списке.

## Пример

Создание задачи:

```bash
curl -X POST http://127.0.0.1:8000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Подготовить доклад по сетям"}'
```

На свежем запуске ответ будет таким:

```json
{"id":1,"title":"Подготовить доклад по сетям","completed":false}
```

Отметка выполнения и статистика:

```bash
curl -X PATCH http://127.0.0.1:8000/tasks/1 \
  -H 'Content-Type: application/json' -d '{"completed":true}'
curl 'http://127.0.0.1:8000/tasks?completed=true'
curl http://127.0.0.1:8000/stats
```

Используйте ID из ответа на создание. Значение `completed` в JSON —
`true` или `false`, без кавычек. В PowerShell эти запросы удобно выполнить
через `/docs`.

## Тесты

```bash
python -m pytest -v
```

35 проверок покрывают маршруты, работу с задачами, ошибки, фильтр, статистику,
настройки, лимит и логи. Каждый тест использует отдельное приложение;
запускать сервер перед тестами не нужно.

Проверка совместимости установленных зависимостей: `python -m pip check`.

## Логи и диагностика

Логи выводятся в терминал с сервером. При `LOG_LEVEL=INFO` видны запуск,
остановка, запросы и изменения задач. Приложение пишет метод, шаблон маршрута,
код ответа и время обработки; содержимое задач в его логи не попадает.
Uvicorn отдельно выводит журнал HTTP-запросов.

Для записи в файл:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8000 > app.log 2>&1
```

Файлы `*.log` исключены из Git.

| Проблема | Решение |
|---|---|
| `No module named fastapi` или `uvicorn` | Активировать окружение и установить зависимости |
| Не найден `app_final` | Запустить команду из папки проекта |
| `Address already in use` | Остановить прежний сервер или выбрать `--port 8001` |
| Не открывается `/docs` | Проверить `/health`, адрес, порт и вывод терминала |
| Ошибка с именем переменной окружения | Исправить значение в `.env` или окружении и перезапустить |
| `404` для задачи | Проверить ID; после перезапуска список пуст |
| `409` при создании | Удалить ненужную задачу или увеличить лимит и перезапустить |
| `422` | Проверить поля, типы данных, название и ID |
| Нет обычных событий в логах | Установить `LOG_LEVEL=INFO` |

## CI

GitHub Actions запускает тесты при `push` и `pull_request`. Workflow также
можно запустить вручную на вкладке **Actions**.
После успешных тестов создаётся artifact `study-tasks-api` с исходниками,
тестами, зависимостями, README, образцом настроек и workflow. Срок хранения —
90 дней. `.env`, виртуальное окружение и `.git` в архив не входят.
